The `LoginCheck` project demonstrates how to compare user-entered credentials against stored values — a pattern that appears in virtually every application that has accounts.

## String comparison with .equals()

In Java you must use the `.equals()` method to compare the **contents** of two strings. The `==` operator checks whether two variables point to the exact same object in memory, not whether they contain the same text.

```java
// Correct — compares the text inside the strings
enteredUsername.equals(username)

// Wrong — compares object references, almost always false for user input
enteredUsername == username
```

<Warning>
Always use `.equals()` (or `.equalsIgnoreCase()`) to compare strings. Using `==` for string comparison is a common beginner mistake that causes validation to fail even when the user types the correct value.
</Warning>

## Simple if/else validation pattern

The `LoginCheck` program stores credentials in variables, collects input with `JOptionPane.showInputDialog`, then uses an `if/else` to check both fields at once with the `&&` operator.

```java LoginCheck.java
// Credentials stored on the "server" side
String username = "mboon";
String password = "asecret";

// Credentials entered by the user
String enteredUsername = JOptionPane.showInputDialog("Enter username");
String enteredPassword = JOptionPane.showInputDialog("Enter password");

// Validation
if (enteredUsername.equals(username) && enteredPassword.equals(password)) {
    System.out.println("Login successful!");
} else {
    System.out.println("Login failed incorrect username or password!");
}
```

Both `.equals()` calls must return `true` for login to succeed. If either one fails, the `else` branch runs.

<Warning>
The credentials in this example (`"mboon"` / `"asecret"`) are hardcoded directly in the source code. This is fine for a learning exercise, but you should **never** store real passwords in plain text in source code in a production application. Real systems store passwords as secure hashes in a database.
</Warning>

## Full example

```java LoginCheck.java
package logincheck;

import javax.swing.JOptionPane;

public class LoginCheck {

    public static void main(String[] args) {

        // Data stored on the website database
        String username = "mboon";
        String password = "asecret";

        // User-entered credentials
        String enteredUsername = JOptionPane.showInputDialog("Enter username");
        String enteredPassword = JOptionPane.showInputDialog("Enter password");

        // Validation
        if (enteredUsername.equals(username) && enteredPassword.equals(password)) {
            System.out.println("Login successful!");
        } else {
            System.out.println("Login failed incorrect username or password!");
        }
    }
}
```

## Swing form version (LoginUI)

`LoginUI.java` is a second version of the same exercise built with a Swing `JFrame` instead of dialog boxes. It provides a proper graphical window with labeled text fields and a **Submit** button.

The key difference is how input is read. Instead of `JOptionPane.showInputDialog`, the form reads values directly from text field components:

```java LoginUI.java
private void btnSubmitActionPerformed(java.awt.event.ActionEvent evt) {
    if (txfUsername.getText().equals("mboon") && txfPassword.getText().equals("verysecret")) {
        lblMessage.setText("Login successful!");
    } else {
        lblMessage.setText("Login failed!");
    }
}
```

The validation logic is identical — `.equals()` compares the text from each `JTextField` against the expected value. The result is displayed by updating the text of a `JLabel` (`lblMessage`) rather than printing to the console.

<Note>
`LoginUI` is generated by the NetBeans GUI Builder (Matisse). The layout code inside `initComponents()` is auto-generated and marked with a warning not to edit it by hand. Focus on the `btnSubmitActionPerformed` method, which contains the logic you write yourself.
</Note>
